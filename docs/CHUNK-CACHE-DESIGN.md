# 区块快照缓存 v4（实验性，默认关闭）

本功能在服务器和 Fabric 客户端之间协商，Velocity 不需要安装插件。新旧端回退到现有 v3/v2；协议号不一致时不绕过跨版本转换。缓存开启时直连也使用普通 Minecraft 隧道，因而不是直接流的性能保证。服务器开启不代表客户端同意写盘。

## 服务器配置

在后端 `plugins/NetSqueeze/config.yml` 设置 `chunk-cache-enabled: true`，重启。首次启动会自动生成 `chunk-cache-namespace`；每个后端必须有独立 UUID，复制配置到其他后端时须重新生成该值。`chunk-cache-epoch` 是操作员维护的失效版本：世界重置、数据包或注册表变更、反透视/权限隐藏规则变更时递增，再重启。不同世界由实际发送字节完整摘要区分，会话内切换维度会重置隧道与快照。**纪元不自动检测所有插件变化，必须由管理员维护。**

`/nsq` 展示完整快照、命中、补丁的选择次数；不是 VC→玩家 TCP 出口字节数，更不是相对当前版本的实测节省。

## 玩家本地授权

默认关闭。聊天输入 `/nsqcache` 查看说明（由客户端拦截，不作为服务器命令发送）。

- `/nsqcache allow`：允许当前服务器地址与玩家账户在本地保存访问过的区块，重新连接后生效。可能包含建筑、方块实体和光照等世界数据。
- `/nsqcache deny`：撤回当前授权并停止后续落盘；已固定的会话内种子保留到断线，避免影响包顺序；不会自动删除旧文件。
- `/nsqcache status`：显示授权、全局磁盘占用和上限。
- `/nsqcache clear`：删除当前连接的缓存范围（地址、账户、后端 UUID/epoch、维度、协议、客户端模组组合）。若环境已变，此命令不包括旧范围；使用 `clear-all` 清理所有范围。
- `/nsqcache clear-all`：删除该模组管理的全部快照，不删除授权；活跃会话可能再次写入，需先 `deny` 再清理。
- `/nsqcache limit 256`：设置全局磁盘上限，单位 MiB，可选 16～1024；设置后重连恢复写入。

授权按客户端选择的地址和账户隔离，不证明服务器身份；后端 UUID 也不是认证凭证。文件写入与读取在单独有界后台队列；队列繁忙时跳过写入。磁盘缓存使用内容 SHA-256，读取时校验并固定在会话内存，缓存损坏、缺失或未预载时不向服务端通告，按完整包处理。SHA-256 不解决服务端伪装，也不会清除外部备份。

## 传输和安全边界

v4 独立频道将每个隧道内包编码为原样、完整快照、固定快照引用或基于已同步快照的补丁，再交给现有 Deflate/ZSTD 编码，故双方字典看到的是同一编码序列。未同步、缓存过大、服务端内存不足或工作队列满时发送完整包。服务端快照生成在有界工作线程；等待期间同连接后续包按序有界排队。无法维持顺序、超时或收到不合法的引用/补丁时，当前实现**关闭连接而不是不安全地回退**；重新连接恢复正常协商。客户端磁盘读写异常不应修改世界或绕过验证。

只处理编码长度 128 B～256 KiB 的 `ClientboundLevelChunkWithLightPacket`，较大区块按完整包处理。每连接快照上限 64 项/4 MiB，服务端全局快照约束 64 MiB；种子每连接最多 64 项/8 MiB，固定至会话结束。补丁是共同前后缀加字面中间片段，并按独立 Deflate 估计是否值得发送；不保证对任意区块或 VC 出口有效。玩家仍需进行客户端区块装载和渲染，节省网络不等于节省所有 CPU。

## 验证状态

请以 GitHub Actions 构建、回归测试和兼容矩阵为准；只有运行成功后才能声明这些检查通过。真实游戏、Velocity、Paper/Folia 和玩家端配置/授权/删档/重连/跨维度/动态光照/反透视/延迟与故障验收由用户自行执行。未来版本、混用转换插件以及任意注册表变更尚无兼容保证。对比流量时，以同场景下 1.4.0 在 VC 实际出口的数据作为基线，分别测冷/热缓存、加载时间、CPU、磁盘和断线率。
