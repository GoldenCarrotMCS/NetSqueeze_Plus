# 区块缓存开发计划与状态

目标：Paper/Folia 后端与 Fabric 客户端通过普通 Minecraft 隧道协商区块快照复用与补丁；Velocity 不安装插件。基线沿用 Java 25 和现有 26.x 矩阵，不引入 Fabric API 或 TabooLib。

## 实现内容

- 新增默认关闭的 v4 能力协商；未授权、未支持或准备超时回退已有 v3/v2。直连开启实验配置时也改用隧道。
- 玩家本地 `/nsqcache allow|deny|status|clear|clear-all|limit`；默认不保存，撤回与清理是独立操作。
- 持久快照按服务器地址、玩家、后端 UUID、纪元、协议、维度与模组列表隔离；验证内容摘要，受全局容量限制。注册表变化依靠管理员递增 epoch，不声称自动检测。
- 会话内有界快照按实际编码字节判断完全相同、小变化补丁或完整发送；旧版本独立频道，不将被替代的原包喂入共享压缩字典。
- 服务端使用有界异步工作队列与有界保序等待；异常、超时或无法保序时断开连接，不声称总可自动回退。客户端缓存不命中时使用完整包。
- 增加快照编解码、损坏、授权和容量测试，以及服务端隧道帧到客户端重组的夹具；实际编译、测试、跨版本兼容与真实游戏验收尚未执行。

## 尚须验证

源码和测试必须交由 GitHub Actions 构建、运行并修复失败项；用户独立验收真实 Velocity、Paper/Folia、客户端 26.2 和玩家交互。未经过验证的源码不是可交付 JAR；未经测量不能保证节省流量或加载更快。
