# 1.6.0 性能优化计划

## 目标与边界

在未发布的 ZSTD 字典功能上减少热路径分配、反射与重复计算，并完成 GitHub 构建/回归/预发布闭环。保留 Java 25、Paper/Folia/Fabric 现有 26.x 基线，不添加 TabooLib、UI、命令、权限或数据库，不改线格式、缓存授权与 8 MiB 安全边界；Velocity 仍无插件。

## 执行与验收

1. 对字典差异做复用、简化、效率和抽象边界审阅，聚焦实际可验证开销；由主任务统一修改，不让审阅任务编辑共享文件。
2. 在不改变字典历史同步和小包 Deflate 行为的前提下减少重复工作；如使用长期原生上下文，必须有界、独占并在断线/失败/移除时释放，不缓存全局玩家数据。
3. 增加回归检查和 GitHub-only 性能证据，检查字典/独立 ZSTD 切换、旧 JNI 兼容、session reset、关闭和错误输入。性能比较明确标注合成数据，不冒充玩家出口实测。
4. 用户已授权自动提交和推送功能分支。提交相关变更、跟进 Actions 全部必需检查及自动预发布，失败则修复再推送；不自动合并、部署游戏端或接受 EULA。
5. 仅在闭环完成或真正阻塞时统一交付。禁止本地构建、编译、测试和服务器/游戏验收。用户自行进行真实跑图验收。

## 已落实的优化

- **跳过不可能胜出的试压**：独立 ZSTD 输出不足 96 字节（32 字节字典摘要 + 64 字节最小收益）时，不再加载字典或做第二次压缩，其他输入保留原来的完整比较。
- **一次编码只建一个压缩上下文**：先编码独立候选，再在同一局部 JNI 上下文加载字典编码候选；函数退出即释放，不使用每玩家长期原生池，不扩大跨帧原生常驻内存。
- **字典更新复用数组和 SHA-256 对象**：字典长度不变时覆盖自己的数组，先完成候选摘要再更新历史；长度变化和关闭仍清零旧数组。不再每帧分配/擦除一个 64 KiB 数组。
- **v5 ACK 按当前会话惰性缓存**：同会话同模式重复访问返回同一 Identifier，pause 更换 UUID 后清除；普通非载荷包跳过 ACK 比较但保持 PLAY 邀请重试和转发。
- **减少重复维护路径**：服务端探测复用共享字典派生；字典校验和要求集中在帧解码器；客户端夹具读写、断言和握手通道复用已有测试代码。

## 验证与范围

新增 `ZstdPerformanceTest` 使用优化前“两次新建上下文”的独立参考编码器，在 level 1/3/5 和相关、修改、高压缩率、高熵数据上比较最终字节与字典摘要。另测 95/96 字节边界、数组复用/变长清零、ACK 身份/会话失效及普通 PLAY 包重试。现有双端真实字典夹具和旧 zstd-jni 独立 JVM 检查继续执行。

这些减少的是明确的操作次数和分配，不是已测得的玩家 FPS、服务器 CPU 百分比或 VC 出口收益。没有新增基准跑分任务、长期原生上下文池、全局玩家字典池，也未重构旧磁盘缓存和协商框架。发布前由 GitHub Actions 执行编译和回归，最终交付报告引用实际运行结果；本地不执行这些测试。
