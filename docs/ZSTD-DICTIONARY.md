# ZSTD 会话字典实施计划

目标：在 1.5.1 已恢复的 ZSTD 大包压缩上，增加每连接 64 KiB 的滚动原始内容字典。字典来自上一条成功发送/解码的 ZSTD 包，不落盘、不上传样本、不跨玩家共享，不改变小包 Deflate 行为。没有外部预训练文件依赖，不在 Netty 线程训练字典。

- 直连使用明确的新 hello/enable 能力，隧道采用独立 v5 频道并显式选择是否携带区块缓存信封；旧 v1/v2/v3/v4 原格式不变。Velocity 无需插件。
- 首条 ZSTD 仍为独立帧，后续比较带字典和不带字典结果，算上 SHA-256 字典摘要和协议开销，至少额外节省 64 字节才使用字典。
- 字典只在确定选择了 ZSTD 并成功编码后更新；高熵回退、小包、失败尝试不推进字典。客户端在完整解码成功后更新同样字节。字典摘要不匹配必须断开，禁止错误回退。
- 保留 8 MiB 窗口、内容长度和单帧检查。兼容 Axiom/Miku 的旧 zstd-jni API；探测实际 loadDict 路径，不依赖 setLongMax。
- 开关 zstd-dictionary-enabled 默认 true，但只有新端互相协商才能启用；增加字典帧和相对独立 ZSTD 的压缩体节省计数，不当作 VC 出口实测。
- 加入服务端实际编码夹具、双端往返、旧库独立 JVM、协商降级、会话重置、错字典/尾随/恶意大小回归测试。
- 本地仅源码和静态检查，不构建、运行测试或游戏/服务器；按用户长期授权完成后自动提交推送并跟进 GitHub 构建。目标版本 1.6.0，云端与实际游戏验收结果必须如实区分。

## 已实现行为与操作

- 版本号更新到 1.6.0。v5 为单独的 offer/data/stop/ack，42 字节邀请含显式缓存开关，不使用 v6。旧客户端可忽略新邀请再选择 v4/v3/v2。新客户端不支持字典时也选择旧邀请。
- 后端 `zstd-enabled: true`、`zstd-dictionary-enabled: true`，默认大包阈值 `65536`，level 1。已有配置即使没有字典开关也按代码默认 true；可显式设 false，重启后回到原来的独立 ZSTD。
- 字典从上一条成功 ZSTD 帧解压后的字节派生（含包长度前缀），前 4 字节固定 NSD1 防止被误识别为训练字典，剩余为尾部最多 65532 字节；这不是预训练 .dict，也不是全局共享库。首包不发送额外字典文件。
- 确定最终选择后双方才更新同一历史。小包 Deflate、高熵回退、区块缓存引用不直接更新字典。启用区块缓存时仅 ZSTD 信封字节参与，不从客户端磁盘任意混入历史。
- marker 2 含 32 字节字典 SHA-256 摘要及带内容校验和的标准 ZSTD 帧。接收前先校验摘要，再做窗口/长度/单帧检查后 JNI 解压；不同步不能继续错误解码。
- 断线、新后端会话、重生/重配置 STOP 或卸载会释放对应历史。单连接额外保留约 64 KiB 字典字节与摘要，同长度更新复用数组；长度变化时有短暂新旧副本，另外还有 JNI 临时工作内存，不是整个压缩器只有 64 KiB。
- 直接连接和无 VC 插件的代理隧道都已接入；无需 `/nsqcache allow` 开启纯内存字典，磁盘缓存仍独立征求授权。字典内容只来自已经允许发送给该玩家的数据，不跨玩家交换。
- 字典探测成功与 `dictionary=true` 仅代表能力；只有 `/nsq` 的“ZSTD 字典帧”增长才是实际选中。累计少传是同包独立 ZSTD 与字典 ZSTD 的压缩体差值（扣除 32 字节摘要），不是与 Deflate 的实测比较，也不是 VC TCP 出口流量。
- 为维持比较准确性，有历史且独立 ZSTD 结果不少于 96 字节时对大包额外压一次；两次试压共用单次调用内的原生上下文。仍会增加 CPU，没有固定节省比例。如果 CPU 成为瓶颈，可关闭字典或提高原有大包阈值后单独测量。
- 客户端紧急禁用仅字典可使用 JVM 参数 `-Dnetsqueeze.zstd.dictionary.disable=true`；不会同时关闭独立 ZSTD。旧 Axiom/Miku 运行库通过 `loadDict(byte[])` 实际往返探测，不再依赖 setLongMax。

## 对现有连接的兼容性

1.6.0 客户端连 1.5.1 后端：后端忽略新 hello/offer 能力，仍用独立 ZSTD；1.6.0 后端连旧客户端：旧端忽略 v5 邀请并选择原有 v4/v3/v2，不会收到 marker 2。双方支持但未授权磁盘缓存时，v5 明确选择 plain，不会误把普通包当成快照信封。字典不增加定时器攒包或额外查询往返；仅已有缓存初始化等待逻辑保持不变。

字典压缩不是区块缓存：它不会让首次需要传输的区块凭空消失，而是复用先前内容减少后续大包压缩体。任何压缩体比较优势都可能被额外 CPU、JNI 初始化、代理外层压缩与帧头影响抵消；默认低压缩级别且允许关闭，不承诺固定收益。
